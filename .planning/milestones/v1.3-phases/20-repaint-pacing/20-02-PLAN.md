<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| QUIC datagram channel → ClientScreen::apply() | Untrusted/duplicate/replayed datagrams arrive; the apply() guard decides what mutates the confirmed grid |
| confirmed_epoch advancement → predictor visibility | Whether confirmed_epoch advances determines whether predicted characters become visible — the noecho leak vector |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-05 | Info Disclosure | apply() guard + confirmed_epoch (noecho leak, R-2) | mitigate | The PRIMARY phase security threat: an attacker observing predicted password characters during `read -s`. Server-side D-20-04 (one epoch per tick, plan 20-01) means confirmed_epoch does not advance per burst datagram; the client guard change to `<` allows same-epoch datagrams to apply WITHOUT advancing last_applied_epoch beyond the tick epoch, so the predictor's tentative-epoch suppression remains intact. Proven by `noecho_read_dash_s_zero_predicted_chars` as a REQUIRED non-#[ignore] CI gate (D-20-09) running with burst delivery active. This is the exact per-datagram-epoch attack vector that caused the 999.4 revert. |
| T-20-06 | Tampering | apply() guard (epoch replay / confusion) | mitigate | The `diff.epoch < self.last_applied_epoch` guard still discards strictly-older (replayed/reordered) datagrams; server epoch is monotonically increasing. Covered by `apply_monotonic_older_epoch_is_noop` + `apply_monotonic_lower_epoch_is_noop`. |
| T-20-07 | Input Validation | apply() out-of-bounds row/col writes | accept | The `<=`→`<` change does not touch the OOB row/col guards inside apply() (ASVS V5, unchanged); same-epoch burst datagrams carry disjoint deferred run subsets so there is no double-write risk. |
| T-20-SC | Tampering | npm/pip/cargo installs | n/a | Phase 20 installs no packages; no Cargo.toml change. No legitimacy gate required. |
</threat_model>
