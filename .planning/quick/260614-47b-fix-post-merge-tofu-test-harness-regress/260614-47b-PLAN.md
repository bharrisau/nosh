# Quick Task 260614-47b: Fix post-merge TOFU test-harness regression

## Problem

Phase 25-03 made `HostKeyVerifier::new` default to `TofuPolicy::Interactive`. Its
first-contact branch calls `tokio::task::block_in_place` (`crates/nosh-auth/src/verifier.rs:154`),
which **panics on a current-thread tokio runtime**. Every native-QUIC integration test in
`crates/nosh-client/tests/auth.rs` and `crates/nosh-client/tests/transport.rs` is
`#[tokio::test]` (current-thread) and connects with an empty `known_hosts` (first contact),
so `block_in_place` panics and double-faults through a quinn mutex, aborting the whole test
binary (first observed hit: `mutual_auth_inprocess_happy_path`). The worktree only ran lib
tests, so the integration suite never exercised this path.

This is test-harness debt, **not** a production bug — `Interactive` is the correct production
default. The fix gives the integration harness a way to build a client with the documented
test-only `TofuPolicy::Silent` (`verifier.rs:139-148`), without changing any production default.

## Constraints (do NOT violate)

- **Do NOT weaken production TOFU.** `make_endpoint`, `make_endpoint_with_transport`, and
  `build_client_config` MUST continue to default to `TofuPolicy::Interactive`. Verify by
  reading the final code — the production entry points keep Interactive.
- The fix is **additive**: add policy-accepting public variants; existing fns delegate to them
  with `TofuPolicy::Interactive`.
- `HostKeyVerifier::with_policy(...)` already exists (`verifier.rs:89`) — reuse it, do not add
  another verifier constructor.
- `TofuPolicy` is already re-exported from `nosh_auth` (`nosh-auth/src/lib.rs:48`) — the
  integration test harness can `use nosh_auth::TofuPolicy`.

## Task 1 — Add policy-accepting client endpoint builders

**Files:** `crates/nosh-client/src/client.rs`

Two call sites currently hardcode `HostKeyVerifier::new(known_hosts, host, provider)`
(Interactive): inside `build_client_config` (~:118) and inside `make_endpoint_with_transport`
(~:169).

Refactor additively so policy is selectable, keeping production defaults intact:

1. Add a public `build_client_config_with_policy(identity, known_hosts, host, policy: nosh_auth::TofuPolicy)`
   that builds the verifier via `HostKeyVerifier::with_policy(known_hosts, host, provider, policy)`.
   Make existing `build_client_config(...)` delegate to it with `TofuPolicy::Interactive` (unchanged behavior).
2. Add a public `make_endpoint_with_policy(identity, known_hosts, host, policy)` mirroring
   `make_endpoint` but threading the policy through `build_client_config_with_policy`.
3. Add a public `make_endpoint_with_transport_and_policy(identity, known_hosts, host, transport, policy)`
   mirroring `make_endpoint_with_transport` but using `HostKeyVerifier::with_policy(..., policy)`.
   Make existing `make_endpoint_with_transport(...)` delegate with `TofuPolicy::Interactive`
   (or keep its body and add the policy variant as the shared impl — either way production stays Interactive).

Re-export `TofuPolicy` from `nosh-client` if convenient (`pub use nosh_auth::TofuPolicy;` in
`client` module or lib), but using `nosh_auth::TofuPolicy` directly in the harness is fine.

- **verify:** `cargo build -p nosh-client` clean; `grep` confirms `make_endpoint`/`build_client_config`/
  `make_endpoint_with_transport` still produce an Interactive verifier.
- **done:** policy-accepting public builders exist; production entry points unchanged.

## Task 2 — Point the integration harness at TofuPolicy::Silent

**Files:** `crates/nosh-client/tests/common/mod.rs`

- `client_endpoint(identity, known_hosts)` → call `client::make_endpoint_with_policy(&identity,
  known_hosts, HOST, nosh_auth::TofuPolicy::Silent)`.
- `client_endpoint_with_qlog(identity, known_hosts, qlog_path)` → use
  `client::make_endpoint_with_transport_and_policy(..., nosh_auth::TofuPolicy::Silent)`.
- Add a brief comment: tests use Silent because they are not exercising the interactive prompt;
  the no-TTY fail-closed and real-auth adversarial paths are covered in Phase 25-04.

- **verify:** the harness compiles; first-contact tests no longer hit `block_in_place`.
- **done:** both harness builders construct Silent-policy clients.
