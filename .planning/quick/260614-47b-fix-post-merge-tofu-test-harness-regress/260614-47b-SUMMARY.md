# Quick Task 260614-47b: Fix post-merge TOFU test-harness regression

## Status: COMPLETE

## Summary

Successfully fixed the test-harness regression where Phase 25-03's `TofuPolicy::Interactive` default caused `block_in_place` panics in integration tests running on current-thread tokio runtime. The fix is purely additive: added policy-accepting public variants while keeping production defaults as `Interactive`.

## Changes Made

### Task 1: Added policy-accepting client endpoint builders

**File:** `crates/nosh-client/src/client.rs`

- Imported `TofuPolicy` from `nosh_auth`
- Added `build_client_config_with_policy(identity, known_hosts, host, policy)` - builds client config with explicit TOFU policy
- Added `make_endpoint_with_policy(identity, known_hosts, host, policy)` - builds endpoint with explicit TOFU policy  
- Added `make_endpoint_with_transport_and_policy(identity, known_hosts, host, transport, policy)` - builds endpoint with custom transport config and explicit TOFU policy
- Modified existing functions to delegate with `TofuPolicy::Interactive`:
  - `build_client_config` → calls `build_client_config_with_policy(..., TofuPolicy::Interactive)`
  - `make_endpoint` → calls `make_endpoint_with_policy(..., TofuPolicy::Interactive)`
  - `make_endpoint_with_transport` → calls `make_endpoint_with_transport_and_policy(..., TofuPolicy::Interactive)`

All production entry points preserve their `Interactive` default (SEC-02 requirement).

### Task 2: Updated integration harness to use Silent policy

**File:** `crates/nosh-client/tests/common/mod.rs`

- Imported `TofuPolicy` from `nosh_auth`
- Modified `client_endpoint` to call `make_endpoint_with_policy(..., TofuPolicy::Silent)`
- Modified `client_endpoint_with_qlog` to call `make_endpoint_with_transport_and_policy(..., TofuPolicy::Silent)`

## Technical Approach

Reused the existing `HostKeyVerifier::with_policy(...)` constructor from `verifier.rs:89` rather than adding a new verifier constructor. The policy parameter threads through the client builder stack:

1. `build_client_config_with_policy` accepts `TofuPolicy` and passes it to `HostKeyVerifier::with_policy`
2. `make_endpoint_with_policy` and `make_endpoint_with_transport_and_policy` expose the policy parameter at the endpoint-builder level
3. Test harness calls the `*_with_policy` variants with `TofuPolicy::Silent`

This respects the constraint that production must use `Interactive` while giving tests a way to opt into `Silent` mode.
