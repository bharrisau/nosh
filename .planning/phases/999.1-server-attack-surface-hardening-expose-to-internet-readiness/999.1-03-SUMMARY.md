# Phase 999.1 Plan 03: Decoder Fuzz Targets (read_message + decode_datagram + decode_epoch_ack + osc_accumulation) Summary

Four fuzz targets overwrite the plan-01 stubs and are proven clean over 200,000 libFuzzer iterations each: `read_message` (length-prefix framing + OnceLock async bridge), `decode_datagram` (StateDiff tag/body/runs-cap), `decode_epoch_ack` (ClientEpoch tag + T-13-01 security guard), and `osc_accumulation` (OSC 52 / title cap assertions on hostile VT byte streams). No crashes found. Seed corpora committed per target.

## What Was Built

**Task 1 — read_message + decode_datagram + decode_epoch_ack (D-01):**

- `fuzz/fuzz_targets/read_message.rs`: uses `static RT: OnceLock<Runtime>` initialised once per fuzzer process via `new_current_thread()`. The body wraps a `tokio::io::BufReader::new(std::io::Cursor::new(data))` and calls `nosh_proto::codec::read_message`. The fuzzer exercises the `MAX_FRAME_LEN` (16 MiB) guard: a `0xFF_FF_FF_FF` prefix triggers `ProtoError::FrameTooLarge` before any `vec![0u8; len]` allocation.

- `fuzz/fuzz_targets/decode_datagram.rs`: single-line `let _ = nosh_proto::datagram::decode_datagram(data)`. Exercises tag-byte check (must be 0x01), postcard body decode, and the T-11-02 DoS guard (`runs.len() > MAX_RUNS` → Err). No `.unwrap()`.

- `fuzz/fuzz_targets/decode_epoch_ack.rs`: single-line `let _ = nosh_proto::datagram::decode_epoch_ack(data)`. Exercises tag check (must be 0x02), the T-13-01 security invariant (0x01 StateDiff tag explicitly rejected), and postcard u64 varint decode.

- Seed corpora generated via a temporary `nosh-proto` example binary using `codec::encode`, `postcard::to_allocvec`, and `encode_epoch_ack` (removed after generation):
  - `read_message`: 5 seeds — valid `SessionClose` frame, zero-len, huge-len-no-body (FrameTooLarge path), truncated body (Io::UnexpectedEof), and `MAX_FRAME_LEN`-declared-len no-body.
  - `decode_datagram`: 6 seeds — valid empty-runs diff, wrong tag 0x02, empty, corrupt body, over-MAX_RUNS diff (4097 runs → Err), valid one-run diff.
  - `decode_epoch_ack`: 7 seeds — epoch=1, epoch=0, epoch=u64::MAX varint, wrong tag 0x01, empty, bad varint (all-continuation-bits), large epoch.

**Task 2 — osc_accumulation (D-01):**

- `fuzz/fuzz_targets/osc_accumulation.rs`: constructs `TerminalState::new(80, 24)`, calls `state.advance(data)`, then asserts both caps:
  - `assert!(payload.len() <= OSC_52_MAX_BYTES)` via `state.osc52_pending()`
  - `assert!(title.len() <= MAX_TITLE_BYTES)` via `state.title()`
  These `assert!` calls are intentional fuzzer signals — a cap-violation panic means the truncation/discard guard in `osc_dispatch` failed.

- Seed corpus: 7 seeds — normal OSC 2 title, normal OSC 52 (base64 "Hello"), 2000-byte title (over `MAX_TITLE_BYTES=1024` — discarded, not stored), 70000-byte OSC 52 raw payload (over `OSC_52_MAX_BYTES=65536` — truncated), incomplete OSC (no BEL terminator), mixed VT stream (CSI + OSC + SGR), OSC 0 combined title.
