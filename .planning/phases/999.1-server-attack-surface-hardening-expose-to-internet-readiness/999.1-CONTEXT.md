# Phase 999.1: Server attack-surface hardening (expose-to-internet readiness) - Context

**Gathered:** 2026-06-06
**Status:** Ready for planning
**Mode:** discuss (interactive, via /gsd:autonomous --interactive — backlog phase promoted)

<domain>
## Phase Boundary

Be confident the nosh server's UDP/443 QUIC ingress is safe to expose to the public internet —
via fuzzing the untrusted decoders + the raw QUIC packet path, and a focused security audit of
everything reachable before/at authentication. Output: no panics / OOM / unbounded growth on
hostile input, plus a documented residual-risk doc.

Motivating goal: the operator wants to expose the service (raw UDP/443, or via a UDP
port-forward / QUIC passthrough) before experimenting with an HTTP/3 reverse-proxy topology.
NOTE (carried into planning, not a task here): a *true* QUIC-terminating HTTP/3 reverse proxy
breaks end-to-end mutual auth + migration (the proxy ends QUIC) — the brief's answer is the
WebTransport-inner-auth topology (M7), which is NOT built. This phase hardens the pre-auth
surface, which is the right prerequisite for raw exposure AND for the inner handshake behind a
future WebTransport tunnel.

Out of scope: the WebTransport/reverse-proxy topology itself (M7); post-auth session logic
beyond pre-auth resource bounds; client-side hardening (that is backlog 999.2); fixing quinn
itself (treated as a maintained dependency, but exercised — see D-02).
</domain>

<decisions>
## Implementation Decisions

### Fuzzing toolchain & decoder targets
- **D-01:** Use **cargo-fuzz / libFuzzer** in a new `fuzz/` sub-crate (nightly — already the
  repo toolchain). Coverage-guided fuzz targets for every untrusted decoder in `nosh-proto`:
  - `codec::decode` — reliable-stream `Message` postcard decode (`codec.rs:51`).
  - `read_message` framing — the length-prefixed reader (`codec.rs:67`) fed from an in-memory
    reader over arbitrary bytes (length-prefix abuse: huge/zero/truncated lengths).
  - `decode_datagram` — datagram `StateDiff`/`DiffRun` (`datagram.rs:430`).
  - `decode_epoch_ack` — `ClientEpoch` (`datagram.rs:183`).
  - OSC accumulation path — the `osc_dispatch` caps / `TerminalControl` accumulation
    (OSC 52 / title; the `MAX_*` byte caps must hold on hostile OSC streams).
  Invariant each target asserts: arbitrary input → `Ok`/`Err` only, never panic / OOM /
  unbounded allocation. Commit a seed corpus per target.

### QUIC packet-layer fuzzing
- **D-02:** ALSO stand up a **raw QUIC-packet fuzzer** firing malformed / oversized / truncated
  UDP datagrams at the server endpoint (and/or feeding bytes into quinn's packet-processing
  entry point). Goal: confirm the server's socket handling + quinn config degrade gracefully on
  hostile packets — no panic, no OOM, no amplification. Explicitly accepted: much of this
  exercises `quinn-proto` (a dependency we don't own); the value is catching OUR endpoint/config
  misuse and validating amplification posture. Document clearly which findings are ours vs
  quinn's.

### CI integration
- **D-03:** Fuzzing is **local-only** — NO CI fuzz job. Commit seed corpus + documented run
  results; deep/long fuzzing is a manual activity. DO add **`cargo audit`** to `.github/workflows/ci.yml`
  as a cheap dependency-CVE gate (it is not a fuzz job). Rationale: time-boxed CI fuzz smokes add
  flake/maintenance for little marginal catch on a small parser surface; the corpus + local runs
  + cargo-audit give the confidence without a long CI job.

### Security scan & output artifact
- **D-04:** Produce a **residual-risk security doc** (SECURITY.md-style, in the phase dir or
  `docs/`) covering the pre-auth audit: (a) unauthenticated/half-open memory caps (the
  `AuthLimits` semaphore = 64 concurrent, 5s auth timeout; datagram receive buffer = 1 MiB;
  per-connection state), (b) amplification potential (QUIC anti-amplification / address
  validation posture — verify quinn defaults are not defeated by our config), (c) pre-auth
  resource exhaustion (CPU/memory under connection floods — `preauth_flood_bounded` already
  exists; extend reasoning). Plus `cargo audit` (CVEs) and `cargo deny` (advisories / licenses /
  banned crates). The doc records what was tested, what holds, and documented residual risk.

### Claude's Discretion
- `fuzz/` target file layout and per-target seed-corpus seeding strategy.
- The exact QUIC-packet fuzzer mechanism (raw UDP socket sends in a test harness vs feeding
  bytes to a `quinn`/`quinn-proto` endpoint in-process) — research informs this.
- Doc filename/location (`999.1-SECURITY.md` in the phase dir vs `docs/SECURITY.md`).
- Whether `cargo deny` runs in CI or is a documented manual/audit step (cargo audit in CI is
  decided; cargo deny placement is discretionary).
</decisions>

<specifics>
## Specific Ideas

- This is expose-to-internet readiness — the bar is "no panic / OOM / unbounded growth on
  arbitrary hostile bytes before authentication," matching CLAUDE.md's DoS-hardening invariant
  ("Cap memory for unauthenticated / half-open connections").
- The existing `preauth_flood_bounded` and `mutual_auth_inprocess_happy_path` integration tests
  (crates/nosh-client/tests/auth.rs) are the behavioural baseline for the connection-flood cap.
- No new runtime dependencies expected in the server/proto crates — fuzz harnesses live in an
  isolated `fuzz/` crate (libfuzzer-sys + arbitrary); cargo-audit/deny are dev tooling.
</specifics>

<code_context>
## Existing Code Insights

### Reusable Assets
- `AuthLimits` + the pre-auth semaphore + auth-timeout already implement the half-open cap — the
  audit (D-04) reasons about and stress-tests these rather than building from scratch.
- nosh-proto decoders are pure functions over `&[u8]` → ideal libFuzzer targets (no async, no I/O).
- `arbitrary` is already a transitive dep (via several crates) — deriving `Arbitrary` for
  structured fuzzing of the decoders is low-friction.

### Established Patterns
- Decoders return `Result<_, ProtoError>` — the no-panic contract is already the intended design;
  fuzzing proves it on arbitrary bytes (incl. malformed postcard, length-prefix abuse).
- The workspace is a Cargo workspace; the `fuzz/` crate is added as a workspace member or a
  nested cargo-fuzz crate per cargo-fuzz convention.

### Integration Points
- `fuzz/` sub-crate depends on `nosh-proto` (decoder targets) and, for D-02, on the server
  endpoint setup (or `quinn`/`quinn-proto` directly) to drive malformed packets.
- `cargo audit` slots into the existing `ci.yml` as an added job/step.

</code_context>
