# Phase 999.1 Plan 04: QUIC Packet Fuzzer (D-02) Summary

Raw QUIC-packet fuzzer feeding arbitrary bytes into quinn-proto's sans-IO `Endpoint::handle` with a production-mirroring endpoint (minimal rcgen cert, `migration(true)`, deterministic `rng_seed`); 200,000 iterations in 5 seconds with no crash.

## What Was Built

**Task 1 — quic_packet fuzzer + seed corpus:**

`fuzz/fuzz_targets/quic_packet.rs` overwrites the Plan 01 stub with a full fuzz target:

- `make_minimal_server_config()`: builds an ephemeral rcgen self-signed cert, converts it to rustls `CertificateDer`/`PrivateKeyDer`, installs the ring crypto provider idempotently, constructs a `rustls::ServerConfig` with no client auth, sets ALPN to `nosh_proto::ALPN` (`b"nosh/0"`), converts to `QuicServerConfig`, wraps in `quinn_proto::ServerConfig::with_crypto()`, applies `nosh_proto::transport_config(false)` (datagram buffers, idle timeout), and calls `migration(true)` — exactly mirroring production wiring.

- `make_server_endpoint()`: `Endpoint::new(EndpointConfig::default(), Some(server_cfg), false /* allow_mtud */, Some([0u8; 32]) /* rng_seed */)` — deterministic PRNG for reproducible crash reproduction.

- Fuzz body: `OnceLock<Mutex<Endpoint>>` built once per process. Per iteration: lock endpoint, convert `data` to `BytesMut`, call `ep.handle(now, remote, None, None, pkt, &mut buf)`, discard result, `buf.clear()` to prevent unbounded growth. Never `.unwrap()` on the result.

Seed corpus — 5 hand-crafted seeds committed:
- `01_quic_initial_v1` (49 bytes): valid QUIC v1 Initial long-header packet (DCID/SCID/token/payload)
- `02_all_zeros` (64 bytes): all-zeros packet (silently dropped)
- `03_single_byte` (1 byte): too short to parse
- `04_invalid_version` (45 bytes): long-header with version `0xBADC0FFE`
- `05_retry_shaped` (55 bytes): packet with Retry type byte (0xF0)

Plus 60 entries from the libFuzzer minimiser after the 200k run — committed for future starting coverage.

## Transport Config Divergence from Production

None. `nosh_proto::transport_config(false)` returns a `quinn::TransportConfig` which is a re-export of `quinn_proto::TransportConfig` — it composes cleanly with `quinn_proto::ServerConfig::transport_config()`. The fuzz endpoint mirrors production exactly: datagram receive/send buffer 1 MiB, max idle timeout 300s, no keep-alive (server side).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] rcgen 0.14 API field mismatch**
- **Found during:** Task 1 (first `cargo +nightly fuzz build` attempt)
- **Issue:** PATTERNS.md showed `cert.key_pair.serialize_der()` but rcgen 0.14 uses `cert.signing_key.serialize_der()` — the `CertifiedKey` struct field is named `signing_key`, not `key_pair`.
- **Fix:** Changed `cert.key_pair` to `cert.signing_key` in `make_minimal_server_config()`.
- **Files modified:** `fuzz/fuzz_targets/quic_packet.rs`
- **Commit:** fe2407c (same task commit)
- **Attribution:** This is an API documentation drift in PATTERNS.md, not a quinn-proto or rustls issue. Our code.

## Crash Classification (Ours vs quinn-proto)

No crashes found during the 200,000-iteration run. The endpoint handled all inputs — including malformed long-headers, truncated packets, invalid versions, and all-zeros inputs — by returning `None` (silently dropped) or `Some(DatagramEvent::Response)` (Version-Negotiation or Stateless-Reset). No panic, no OOM, no unbounded allocation.

Classification framework for future crashes (documented for Plan 05):
- **Ours:** panic in `make_minimal_server_config()`, `make_server_endpoint()`, or the lock/BytesMut conversion path → fix + regression + corpus entry in this crate.
- **quinn-proto's:** panic inside `Endpoint::handle()` on malformed input → do not fix quinn internals; file upstream issue with repro bytes; record in Plan 05 security doc with attribution.
