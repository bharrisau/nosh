<objective>
Prove SC#4: a simulated network change in WebTransport mode resumes the server-side
session with byte-exact replay and a rotated token, with no shell disruption beyond a
reconnect. The production machinery already exists (verified in RESEARCH.md) — this plan
adds the missing integration test that exercises the full WT drop → reconnect → inner
auth → Reattach → replay path end to end over a real WebTransport connection, and
documents the WT session-loss detection contract at its source.

Purpose: WT-06 / SC#4 currently has no integration coverage over a real WT connection.
The native-QUIC equivalent is covered (reattach.rs), but the WT path (inner-auth-gated
reattach on the authenticated control stream) is untested end to end. Without this test,
a regression that broke WT reattach (e.g. a stray open_bi before auth, an off-by-one on
highest_applied, or a token-rotation regression) would ship silently.

Output: a new `wt_reattach.rs` integration test under the `webtransport` feature, plus a
source doc comment recording which read paths surface a dropped WT session as
`PumpOutcome::TransportDrop`.
</objective>

## Planner discretion calls (resolved here, recorded for traceability)

### Keystroke buffering during the reconnect gap — DEFERRED
CONTEXT.md lists keystroke buffering under **Claude's Discretion** (NOT a locked decision);
RESEARCH.md §"Keystroke Buffering" states it is optional and "The success criteria (WT-06,
SC#1-SC#4) do not explicitly require keystroke buffering."

**Decision: defer.** None of the four Phase 26 success criteria require it. SC#4's
"seamless resume" is satisfied by byte-exact output replay (covered by Task 1); buffering
keystrokes typed during the sub-second-to-few-second gap is a UX refinement that would add a
stateful bounded queue across the `run_pump` boundary (RESEARCH.md Assumption A3 flags a
possible signature change to `reattach_session_on_stream`) — production code, not a test, and
outside the WT-06 mandate. Deferring keeps the phase scoped to its requirement and avoids
touching the reconnect supervisor's hot path. If a future UAT (Phase 28) surfaces lost
keystrokes as a real defect, raise it as a tracked gap-closure or backlog item then.

### Network-change simulation mechanism — RESOLVED (client transport drop)
CONTEXT.md "Pending Decision #1" asked the planner to pick the SC#4 drop mechanism against the
built transport. Resolved to **client-side transport drop** (drop the `connect_wt` transport)
rather than server-side `conn.close`: the `WtTestServer` harness does not expose the active
`wtransport::Connection`, so a client drop is the hook-free, deterministic equivalent — the
server orphans the slot on `TransportLost` either way (server.rs:1500). Recorded inline in
Task 1.
