<objective>
Close the post-authentication OSC OOM vector (SEC-03): bound OSC accumulation at 1 MiB BEFORE the bytes reach vte's unbounded `osc_raw` buffer, and resync the parser to ground state on overflow so subsequent PTY output still renders. Prove it with a RED-before / GREEN-after multi-chunk regression test.

Purpose: vte 0.15 with `feature = "std"` accumulates `osc_raw` as an unbounded `Vec<u8>` across `advance()` calls until the terminator. The existing `OSC_52_MAX_BYTES`/`MAX_TITLE_BYTES` caps run in `osc_dispatch` — after vte has already allocated the full payload. A buggy or hostile app emitting a giant multi-chunk OSC can exhaust server memory and orphan every session. This bound must intercept earlier (D-19-01/02/03).
Output: `OSC_ACCUMULATION_MAX` constant, an `osc_byte_count` field, a pre-filter in `advance()`, parser resync on overflow, and an extended fuzz target + deterministic multi-chunk regression test.
</objective>

advance() (terminal.rs ~222-226): `pub fn advance(&mut self, bytes: &[u8]) { let mut parser = std::mem::take(&mut self.parser); parser.advance(self, bytes); self.parser = parser; }`. The OSC pre-filter must compute a (possibly truncated) byte slice BEFORE this mem::take/advance, then on overflow replace the parser with `vte::Parser::default()` (= State::Ground, the #[default] variant) and reset osc_byte_count = 0.

Existing constants (terminal.rs ~47-63): `OSC_52_MAX_BYTES = 65_536`, `MAX_TITLE_BYTES = 1_024` (pub const, storage caps in osc_dispatch — unchanged). Add `pub const OSC_ACCUMULATION_MAX: usize = 1_048_576;` (1 MiB) following the same doc+const pattern. New field `osc_byte_count: usize` (init 0 in new(), reset 0 in RIS).

OSC framing: start = ESC ] (0x1B 0x5D) or single-byte 0x9D; end = BEL (0x07) or ST (ESC \ = 0x1B 0x5C). The pre-filter tracks an `in_osc`/counter state across calls (vte's internal State is private) — count bytes while inside an OSC, reset count at start and end, truncate the slice at the byte that would exceed 1 MiB then resync.

esc_dispatch RIS (`b'c'` ~741-757): must also reset osc_byte_count = 0 (alongside saved_primary from plan 01).

Fuzz target (fuzz/fuzz_targets/osc_accumulation.rs ~1-31): imports `{TerminalState, OSC_52_MAX_BYTES, MAX_TITLE_BYTES}`, calls state.advance(data) once, asserts osc52_pending()/title() caps. max_len default 4096 cannot reach 1 MiB via fuzz data alone — construct the oversized OSC deterministically and drive in chunks.

Existing analog test: `adversarial_large_osc_title_is_bounded_no_panic` (terminal.rs ~1502-1538) — single-chunk 64 KiB. The new multi-chunk test mirrors its shape but loops state.advance() over chunks of a 10 MiB payload.
