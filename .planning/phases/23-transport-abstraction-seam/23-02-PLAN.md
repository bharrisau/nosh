<objective>
Refactor the `nosh-server` session pump to be transport-agnostic over the Plan 01 traits, with a pure pass-through Quinn wrapper. After this plan, `run_session`, `run_reattach_session`, `send_burst`, `handle_connection`, `run_channel_task`, `run_scrollback_sender_task`, `run_echo_loop`, and `read_varint_u32` no longer reference concrete `quinn::Connection` / `quinn::SendStream` / `quinn::RecvStream`; they go through `NoshTransport` / `NoshSendStream` / `NoshRecvStream`. `ChannelEvent::Stream` carries boxed trait streams.

Purpose: WT-01 + ROADMAP SC#2/SC#3/SC#4 + D-02/D-03/D-04. This is the seam Phase 24 plugs the WebTransport wrapper into. It is a PURE no-behaviour-change refactor — D-05 (zero test modifications) is the acceptance bar; any required test edit means the refactor changed behaviour, so STOP and reconsider rather than editing a test.
Output: `crates/nosh-server/src/quinn_transport.rs` (new) + refactored `server.rs` / `channel.rs`.

SCOPE BOUNDARY (resolves 23-RESEARCH.md Open Question 2 and the PATTERNS.md open question): The CLIENT side is intentionally NOT converted in this phase. `nosh-client/src/client.rs` helpers (`open_session`, `open_session_with_token`, `open_channel`, `send_reattach`, `send_input`, `send_resize`, `send_ack`, `await_reattach_reply`, `collect_until_close`, `reattach_collect`, `run_session_collect`, `stream_echo_roundtrip`) and `nosh-client/src/channel.rs` (`run_channel_task`, `run_scrollback_drain_task`) STAY on concrete quinn types. Reason: ~12 integration test files in `crates/nosh-client/tests/` call `conn.open_bi()` directly and pass the returned concrete `quinn::SendStream`/`quinn::RecvStream` to `nosh_proto::read_message`/`write_message` (which require `AsyncRead`/`AsyncWrite`), call `ch_send.finish()`/`read_exact`/`read` on them, and declare helper params as `&mut quinn::RecvStream` (e.g. `read_pid`, `send_request_read_page`). Converting these to `Box<dyn ...>` would force test edits → a direct D-05 violation. D-03 names the SERVER session-pump functions; the client helpers are test-support that D-05 protects. The `stream_echo_roundtrip` `read_to_end` concern from PATTERNS.md is therefore moot — that helper stays on `&quinn::Connection`. The client WebTransport path is Phase 24 scope (YAGNI). Do NOT create `nosh-client/src/quinn_transport.rs` in this phase.
</objective>

<threat_model>
This plan is a pure no-behaviour-change refactor of internal server code. It adds no external input, no new network surface, no new auth path, and no new parsing of untrusted bytes. The load-bearing security invariants from CLAUDE.md must be preserved exactly, not weakened.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> server QUIC connection | Untrusted peer crosses here. UNCHANGED by this refactor — the same quinn connection, same TLS mutual auth, same pre-auth DoS Semaphore in run_accept_loop. The trait sits BELOW this boundary (it only abstracts I/O after the connection exists). |
| auth -> session dispatch | extract_peer_identity (client cert -> identity) runs on the raw quinn::Connection BEFORE QuinnTransport boxing. The refactor must keep this ordering; moving auth onto the trait would be a regression. |
