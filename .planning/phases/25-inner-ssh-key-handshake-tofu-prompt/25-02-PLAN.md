<objective>
Implement the server side of the WebTransport inner SSH-key handshake (D-02: WT only — the native QUIC path is untouched). Add `run_inner_auth_server` (the `Unauthenticated → ChallengeExchanged → Authenticated` state machine, D-05), implement `WtransportTransport::export_keying_material` (D-01 channel binding), replace the `handle_connection_wt` test stub with a real gate, and thread `authorized_keys` + the host signer through `run_wt_accept_loop` from `main.rs`.

Purpose: this is the gate that makes WebTransport mode actually secure — without it any peer reaching the endpoint is authenticated. The EKM-in-transcript binding is the highest-severity mitigation in the milestone (WT-3 transparent-proxy MITM) and cannot be retrofitted after the wire format ships.
Output: `run_inner_auth_server` returning the authenticated `NoshPublicKey`; server WT `export_keying_material`; `handle_connection_wt`/`run_wt_accept_loop` signatures carrying `authorized` + `host_signer`; `main.rs` WT arm wiring; `sha2`+`getrandom` added to nosh-server.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WebTransport client → server control stream | Untrusted; the only thing standing between a remote peer and a PTY is run_inner_auth_server |
| Terminating proxy → server | The proxy holds a different outer-TLS leg; it must not be able to relay a client's signed exchange (WT-3) |
| Reattach token → session | A stolen token must be useless before authentication completes (MH-1) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-02-WT3 | Spoofing | transcript / channel binding | mitigate | EKM from `export_keying_material` folded into both signed transcripts; a proxy on a different TLS leg derives a different EKM → client signature fails verification (Task 1 step 6) |
| T-25-02-MH1 | Elevation of privilege | SessionOpen/Reattach before auth | mitigate | `handle_connection_wt` reads the first session frame ONLY after `run_inner_auth_server` returns Ok (Task 2); state machine D-05 |
| T-25-02-WT4 | Repudiation | challenge replay | mitigate | `server_nonce` is fresh 32-byte CSPRNG per `run_inner_auth_server` call (single-use); a replayed prior response signs over a stale nonce → verify fails |
| T-25-02-ORACLE | Information disclosure | failure path | mitigate | All failures send the single fieldless `InnerAuthFail`; signature verified before authorized_keys check in fixed order (Pitfall 5); only fingerprints logged (D-04/D-07) |
| T-25-02-DOS | Denial of service | blocking ssh-agent / host sign | mitigate | Host signing wrapped in `spawn_blocking` so it cannot starve the tokio event loop (Pitfall 7) |
| T-25-02-BYPASS | Tampering | test-support inner-auth bypass | mitigate | Bypass gated behind `cfg(any(test, feature = "test-support"))`; release builds always run real inner auth (T-24-03-E discipline preserved) |
| T-25-02-SC | Tampering | cargo installs (sha2, getrandom) | accept | Already-vetted RustCrypto/getrandom crates added as direct deps; RESEARCH Package Legitimacy Audit: no new external packages |
