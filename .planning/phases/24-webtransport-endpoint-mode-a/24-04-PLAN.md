## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → outer TLS (server CA cert) | The client validates the server's CA-signed cert via the OS trust store (Mode A, D-05); this proves server identity but inner SSH-key auth (Phase 25) is the authoritative mutual auth |
| CLI flag → transport selection | `--webtransport` explicitly selects the protocol (WT-05 client side) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-04-S | Spoofing | server identity via outer TLS | accept | Mode A uses `with_native_certs` standard CA validation; end-to-end identity is the inner SSH-key handshake (Phase 25). A self-signed-cert bypass exists ONLY in the documented test-only config variant, never the default `build_wt_client_config` |
| T-24-04-I | Information Disclosure | un-awaited `finish()` on WT streams | mitigate | The client wrapper's `finish()` is async and every pump call site (from Plan 02) uses `.finish().await`; the consuming `stop()` via `Option::take()` prevents double-stop |
| T-24-04-D | Denial of Service | retry storm on dial failure | accept | WT dial errors flow through the existing `is_fatal_connect_error` + exponential backoff supervisor (unchanged from native mode) |
</threat_model>
