<objective>
Harden the client against a malicious/compromised server (SEC-04). nosh's structured datagram path (StateDiff cells, not raw bytes) already blocks arbitrary VT injection; this plan closes the remaining raw-byte gaps on the reliable-stream `TerminalControl` re-emit path and the control-stream channel/data handling, per D-02..D-07.

Two real gaps the research MEASURED and this plan MUST fix: (1) the title filter strips `\x1b`/`\x07` but MISSES `\r`/`\n` (CR-overwrite social-engineering vector); (2) the clipboard selection field strips escapes but has NO whitelist. Plus: reject OSC 52 read form, validate channel-IDs, cap PtyData, and implement the locked OSC 8 scheme whitelist (D-07).

D-02 resolution (stated explicitly, do not invent): the client has NO `vte::Parser` — it consumes structured StateDiffs + discards raw PtyData. The authoritative per-OSC byte gate is the SERVER-side `osc_prefilter` (re-verified in 27-01). D-02 is therefore satisfied by the server-side prefilter + the client's structured path; Task 1 adds a confirming guard test that the client crate runs no unbounded OSC accumulator. D-04 (DCS/PM/APC) is likewise already a no-op — there is no client vte parser and `TerminalControlPayload` has no DCS/PM/APC variant; Task 1 adds a documenting guard test, no new stripping code.

Purpose: the server must be safe before it is internet-exposed in Phase 28. Output: a hardened client + the new Hyperlink protocol variant + server-side OSC 8 decode.
</objective>
