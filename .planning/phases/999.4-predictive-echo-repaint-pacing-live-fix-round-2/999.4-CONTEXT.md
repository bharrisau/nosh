(2026-06-05, native Windows client vs Linux server at ~150 ms RTT). Three concerns:

<decisions>
## Implementation Decisions

### Repaint pacing — burst datagrams per tick
- **D-01:** The server session pump currently sends at most ONE MTU-capped state-diff datagram
  per 16 ms tick (`nosh-server/src/server.rs:580` diff_interval; `:676-712` send; overflow →
  `pending_deferred`). The terminal model is ALREADY decoupled from the send — PTY output is
  fed into the model on the `out_rx.recv()` arm via `slot.push_output_and_parse()`
  (`server.rs:612`), so the full final screen state is available at tick time. The fix: on each
  diff tick, drain the full deferred diff into **as many MTU-capped datagrams as needed**
  (not just one), bounded by a **congestion-aware per-tick budget** so a huge repaint cannot
  flood the path. Keep the loss-tolerant latest-wins datagram path (the client already
  reconciles); do NOT switch to the reliable stream. Goal: a full-screen repaint (vim startup,
  multi-line paste) lands in ~1 RTT instead of dribbling over many ticks × RTT.
- **Confirmed mechanism (answers the user's question):** there is no "ack to vim" gating output
  and no QUIC flow-control ceiling (datagrams are not ack-gated; send buffer is 1 MiB,
  `transport.rs:9`). The only limiter is the one-datagram-per-tick policy.
- **Direction artefact** (vim top-down / paste bottom-up) is the `build_state_diff` cell-walk +
  deferral order; bursting the whole diff per tick makes it moot for repaints that fit the
  per-tick budget.

### read -s — predict the command-submitting Enter's line-advance
- **D-02:** On standard SSH, pressing Enter at the `read -s SECRET; echo done` prompt drops the
  caret to the next line immediately (the command line was echoed); subsequent secret keypresses
  are hidden; the final Enter prints `done` and a fresh prompt. nosh today leaves the caret on
  the command line until the shell reprints. Fix: positively predict the **Enter line-advance**
  (predicted cursor → col 0 of next row, with scroll-at-bottom handling), Mosh-style, when Enter
  is pressed at an echoing prompt — instead of only doing `EpochReset` (`predictor.rs:415`). The
  existing structural noecho/tentative-epoch machinery already suppresses the subsequent hidden
  secret characters (`confirmed_epoch` never advances under `read -s`), so this naturally yields
  the user's model: "handle the first Enter normally, THEN enter secret mode." Must not
  mispredict during the hidden secret entry, and must not regress the 999.3 noecho tests or the
  CR-01/`reset_with_cursor` epoch-start-col behaviour.

### Fast-typing glitch — instrument first, then fix
- **D-03:** Symptom: holding a key or mashing the keyboard makes letters appear to disappear
  (client overlay), very easy for the operator to reproduce; not seen when typing slowly. Likely
  cause: a mid-burst `reset()` (e.g. an `EpochReset`/`BulkSuppressed` classification, or a cull
  interaction) clears already-shown pending predictions, so letters vanish until the next
  confirming datagram (~RTT later). Deliverable, in order:
  1. **Instrumentation** — a predictor decision-trace (gated `tracing` debug events) recording,
     per input batch: the classification (PredictChar/PredictBatch/EpochReset/BulkSuppressed/…),
     pending-prediction count before/after, any `reset()`/cull and how many pending predictions
     were dropped, and the predicted vs confirmed cursor. Enough for the operator to reproduce
     (mash/hold) and for us to see exactly when/why letters disappear. This is the primary
     deliverable the user asked for ("give me the tools to instrument it").
  2. **Hypothesis fix + regression test** — if the captured trace (or a reasoned repro) confirms
     the mid-burst-reset-drops-pending theory, fix it so a burst that stays printable does not
     discard already-shown predictions, with a fail-before/pass-after test.
  3. If the captured behaviour turns out to be a different root cause, the instrumentation lands
     and the precise fix is a fast follow once the operator sends a capture.

## Existing Code Insights

### Reusable Assets
- Session-pump `diff_interval` + `build_state_diff` + `pending_deferred` — the exact seam for
  D-01; change the per-tick send from single-datagram to bounded-burst.
- `nosh::predict` tracing events already in `run_pump` — extend for the D-03 decision trace.
- `predictor.rs` `InputAction` match + tentative-epoch machinery — the seam for D-02 newline
  prediction and the D-03 burst-reset fix; mirror the existing adversarial test style.

### Established Patterns
- Terminal model is fed independently of the send (decoupled) — D-01 does not need to touch the
  read path.
- Datagrams are latest-state-wins and the client reconciles — bursting is safe w.r.t. loss.
- Adversarial fail-before/pass-after tests in predictor.rs / screen.rs — mirror for new tests.

### Integration Points
- D-01 is server-only (`server.rs`); D-02/D-03 are client-only (`predictor.rs`, `main.rs`,
  maybe `screen.rs`). The two halves are independent and can be separate plans/waves.
