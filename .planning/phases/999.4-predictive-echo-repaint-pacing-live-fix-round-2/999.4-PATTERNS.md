**Replacement pattern** — single `if let Some` becomes a `loop`:
```rust

    if !resume_complete {
        continue;
    }
    let cap = match conn.max_datagram_size() {
        Some(c) if c >= MIN_CAP => c,
        _ => continue,
    };
    loop {
        // Budget gate: stop if Layer 1 queue has < one datagram's worth of free space.
        // conn.datagram_send_buffer_space() confirmed on quinn::Connection 0.11.9.
        // Verify method name at implementation time (RESEARCH Pitfall 1).
        if conn.datagram_send_buffer_space() < cap {
            break;
        }
        let deferred = std::mem::take(&mut pending_deferred);
        match build_state_diff(
            &slot,
            &mut current_epoch,
            last_acked_epoch,
            &last_acked_snapshot,
            &last_sent_snapshot,
            deferred,
            cap,
        ) {
            None => break,
            Some(result) => {
                epoch_snapshots.push_back((result.epoch, result.sent_cells.clone()));
                if epoch_snapshots.len() > EPOCH_SNAPSHOT_CAP {
                    epoch_snapshots.pop_front();
                }
                last_sent_snapshot = result.sent_cells;
                let no_more = result.deferred.is_empty();
                pending_deferred = result.deferred;
                if let Err(e) = conn.send_datagram(result.payload) {
                    use quinn::SendDatagramError::*;
                    match e {
                        TooLarge => {}
                        UnsupportedByPeer | Disabled => break SessionEnd::TransportLost,
                        ConnectionLost(_) => break SessionEnd::TransportLost,
                    }
                }
                if no_more { break; }
            }
        }

Note: `break SessionEnd::TransportLost` inside a nested `loop` inside the `loop { ... session_end ... }` requires a labelled outer loop. Add `'pump: loop {` at line 597 and use `break 'pump SessionEnd::TransportLost` in the send error arms. Verify the existing break syntax at implementation time.

InputAction::PredictEnter => {
    // D-02: predict the Enter line-advance, Mosh newline_carriage_return style.
    // 1. Clear pending (same as EpochReset — we cannot know noecho state yet).
    // 2. become_tentative (new epoch — subsequent chars hidden until confirmed).
    // 3. Predict cursor → (row+1, col 0) if not at last row; (row, col 0) on last row.
    // The noecho tentative machinery handles suppression structurally (no explicit flag).
    self.pending.clear();
    self.become_tentative();
    self.cursor_motion_pending = false;
    self.needs_epoch_start_sync = true;
    let row = self.predicted_cursor.row;
    if row < self.term_rows.saturating_sub(1) {
        // Normal case: advance to next row, column 0.
        self.predicted_cursor = CursorPos { row: row + 1, col: 0 };
    } else {
        // At last row: cursor stays at (row, 0) — scroll is unpredictable.
        // Mosh does NOT predict scroll; we match that (RESEARCH Q2).
        self.predicted_cursor = CursorPos { row, col: 0 };
    }
    self.cursor_motion_pending = true;
}
```

**Source:** `crates/nosh-server/src/server.rs` lines 704–711

### Adversarial test doc-comment style

**Source:** `crates/nosh-client/src/predictor.rs` lines 1929–1966, 2057–2114, 2158–2220
**Apply to:** all new tests for D-02 and D-03

Pattern:
1. Doc comment: one-sentence summary of the BUG/decision tag.
2. Doc comment: "Before the fix, [old behaviour]." then "After the fix, [new behaviour]."
3. First lines of test body: `// FAIL BEFORE FIX: [what was wrong].` and `// PASS AFTER FIX: [what now passes].`
4. Assertion message: `"[DECISION-TAG]: [human-readable failure description]"` — includes enough context that a cargo test failure output is self-explanatory without reading the code.

### `reset()` vs `become_tentative()` — when to use each

**Source:** `crates/nosh-client/src/predictor.rs` lines 582–622

- `reset()` (lines 585–596): clears `pending`, calls `become_tentative()`, sets `cursor_motion_pending = false`, `needs_epoch_start_sync = true`. Use when fully abandoning the current prediction set.
- `reset_with_cursor(confirmed)` (lines 608–622): same as `reset()` but also force-sets `predicted_cursor = confirmed`. Use when the confirmed cursor is reliable and the stale predicted cursor must be corrected (EpochReset / Enter after noecho).
- `become_tentative()` (lines 578–580): increments `prediction_epoch` only. Use when existing predictions should remain visible but new ones are tentative (D-03 hypothesis fix for BulkSuppressed with pending>0).
