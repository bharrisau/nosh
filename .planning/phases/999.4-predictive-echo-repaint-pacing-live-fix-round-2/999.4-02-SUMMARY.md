# Phase 999.4 Plan 02: Predictive-echo D-02/D-03 Fix Summary

D-03 instrumentation (per-on_input decision-trace), D-02 PredictEnter line-advance, and D-03 BulkSuppressed hypothesis fix — all in predictor.rs.

## What Was Built

**Task 1 — D-03 instrumentation (91bb14b):**

Added `action_kind_tag()` helper mapping every `InputAction` variant to a static string tag with no char/byte content (T-15-08). Added `PredictEnter` stub to `InputAction` enum (filled in Task 2). Instrumented `on_input` with one `tracing::debug!` event (target `nosh::predict`, `event = "on_input"`) after the match block, recording: `batch_len`, `action` (kind tag), `pending_before`, `pending_after`, `predictions_dropped`, `pred_row`, `pred_col`. Exactly one event per `on_input` call.

**Task 2 — D-02 PredictEnter (9abaaf4):**

Replaced `classify_input` Enter arm (`b"\r"` / `b"\n"`) from `EpochReset` → `PredictEnter`. Tab, ESC, and other controls remain `EpochReset`. Added full `PredictEnter` on_input arm mirroring `reset_with_cursor` field order: `pending.clear()` → `become_tentative()` → `cursor_motion_pending = false` → `needs_epoch_start_sync = true` → `epoch_start_col = 0` → advance predicted cursor to `(row+1, 0)` if `row < term_rows-1` else `(row, 0)` (scroll-at-bottom: no advance, matching Mosh) → `cursor_motion_pending = true`.

Renamed `classify_enter_epoch_reset` → `classify_enter_predict_enter` (asserts PredictEnter for CR and LF). Added `enter_predicts_line_advance_cursor` (row 5 → (6,0), cursor_motion_pending true) and `enter_at_last_row_stays_on_row` (row 23 of 24 → (23,0), no advance). Updated `bug_d`, `bug_f`, and `cr01` tests to reflect PredictEnter semantics.

**Task 3 — D-03 BulkSuppressed hypothesis fix (799f147):**

Changed `BulkSuppressed` arm from unconditional `self.reset()` to: if `self.pending.is_empty()` → `self.reset()` (harmless); else → `self.become_tentative()` + `self.needs_epoch_start_sync = true`. This preserves already-visible predictions across a mash/key-repeat burst that classifies as BulkSuppressed, preventing the "letters disappear" glitch until cull() reconciles on the next datagram (~RTT).

Added `bulk_suppressed_does_not_drop_existing_predictions`: after typing 'a' (pending=1), sending `b"ab\x1bcd"` (BulkSuppressed) must preserve pending=1. Confirmed `b"ab\x1bcd"` classifies as BulkSuppressed via pre-existing `classify_bulk_suppressed_with_escape_still_suppresses` test.

## Deviations from Plan

**1. [Rule 1 - Bug] Updated bug_d test: Enter post-motion now returns Some(cursor) not None**

Found during: Task 2
Issue: `bug_d_arrow_motion_moves_caret_and_survives_sync` asserted `predicted_cursor().is_none()` after pressing Enter, with comment "Enter (epoch reset) clears motion". With D-02, Enter calls PredictEnter which sets `cursor_motion_pending = true`, so `predicted_cursor()` returns `Some(CursorPos { row: 1, col: 0 })`.
Fix: Updated assertion to `assert_eq!(overlay.predicted_cursor(), Some(CursorPos { row: 1, col: 0 }), ...)`.
Files modified: crates/nosh-client/src/predictor.rs
Commit: 9abaaf4

**2. [Rule 1 - Bug] Updated bug_f test: Enter now predicts (row+1, 0), not snap-to-confirmed**

Found during: Task 2
Issue: `bug_f_enter_after_noecho_syncs_caret_from_confirmed` expected `predicted_cursor == confirmed_cursor` after Enter (old EpochReset → reset_with_cursor behaviour). With D-02, PredictEnter predicts (stale_row+1, 0) from the current predicted row.
Fix: Updated doc-comment and assertions to reflect D-02 semantics — after PredictEnter from row 0, cursor is at (1, 0).
Files modified: crates/nosh-client/src/predictor.rs
Commit: 9abaaf4

**3. [Rule 1 - Bug] CR-01 test: switched trigger from Enter to Tab to preserve test intent**

Found during: Task 2
Issue: `cr01_reset_with_cursor_epoch_start_col_follows_new_prompt_not_pre_enter` used Enter to trigger the EpochReset → reset_with_cursor chain. With D-02, Enter no longer calls reset_with_cursor. The CR-01 regression (reset_with_cursor must not lock epoch_start_col) is still tested, but via Tab (which still calls EpochReset → reset_with_cursor).
Fix: Changed trigger from `b"\r"` to `b"\t"`, updated comments and assertions accordingly.
Files modified: crates/nosh-client/src/predictor.rs
Commit: 9abaaf4

**4. [Rule 2 - Missing critical functionality] PredictEnter sets epoch_start_col=0**

Found during: Task 2
Issue: PredictEnter predicts cursor at col 0 (new line start), but `epoch_start_col` was not updated. Backspace clamp would use the stale `epoch_start_col` from the previous epoch, potentially blocking backspace at an incorrect position (e.g., col 6 from the previous prompt, while predicting col 0 for the new line).
Fix: Added `self.epoch_start_col = 0` in PredictEnter arm — clamps backspace at the predicted position. `sync_cursor_from_confirmed` updates `epoch_start_col` to the actual prompt col once cursor_motion_pending clears and pending empties after cull.
Files modified: crates/nosh-client/src/predictor.rs
Commit: 9abaaf4
