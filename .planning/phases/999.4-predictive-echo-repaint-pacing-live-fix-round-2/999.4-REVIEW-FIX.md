## Fixed Issues

### WR-01: BulkSuppressed/become_tentative sets needs_epoch_start_sync incorrectly mid-epoch

**Files modified:** `crates/nosh-client/src/predictor.rs`
**Commit:** d345d81
**Applied fix:** Removed `self.needs_epoch_start_sync = true;` from the
`BulkSuppressed` else-branch (the become_tentative path, active when
`pending.len() > 0`). A BulkSuppressed burst fires mid-epoch (during active
typing), not at a prompt boundary. Setting the flag would cause the next
`sync_cursor_from_confirmed` call to overwrite `epoch_start_col` with the
mid-line confirmed column, misplacing the backspace/cursor-left clamp floor
(BUG-E reintroduced). The existing `epoch_start_col` set at the true prompt
boundary is preserved. A detailed comment explains the invariant.

Added required adversarial regression test
`wr01_mid_epoch_bulk_suppressed_does_not_tighten_epoch_start_col`: establishes
`epoch_start_col = 2`, types "abc", fires mid-epoch BulkSuppressed (pending > 0),
then confirms via `sync_cursor_from_confirmed` at col 5. Asserts that
`epoch_start_col` remains 2 and that backspace still clamps at col 2 after the
burst — reproducing the BUG-E symptom (fail-before / pass-after style, tagged
WR-01 / BUG-E in assertions).

### WR-02: D-03 trace event skipped on four early-return paths in on_input

**Files modified:** `crates/nosh-client/src/predictor.rs`
**Commit:** d345d81
**Applied fix:** Introduced a `macro_rules! trace_exit!` at the top of
`on_input` (after the `action_kind` capture, before the `match`). The macro
body is identical to the previous single `tracing::debug!` call. Replaced the
four early `return` statements with `trace_exit!(); return;` pairs:

1. `PredictChar` during `in_bracketed_paste` (was line ~340)
2. `PredictChar` wide-char right-edge guard (was line ~347)
3. `PredictBatch` during `in_bracketed_paste` (was line ~494)
4. `PredictBatch` wide-char right-edge guard (was line ~505)

Replaced the trailing `tracing::debug!` call at the end of `on_input` with
`trace_exit!()`. Every `on_input` call now emits exactly one trace event on
all exit paths. T-15-08 (no char/byte content) is preserved — `action_kind_tag`
returns a static string tag with no character content. No double-logging: the
macro replaces the trailing call, it does not add to it.

### IN-01: Dead write to cursor_motion_pending in PredictEnter arm

**Files modified:** `crates/nosh-client/src/predictor.rs`
**Commit:** d345d81
**Applied fix:** Removed `self.cursor_motion_pending = false;` from the
`PredictEnter` arm. This assignment was unconditionally overwritten by
`self.cursor_motion_pending = true;` seven lines later with no observable
read between the two writes (no call to `sync_cursor_from_confirmed` or
`predicted_cursor` occurs within `on_input`). Replaced the dead write with
an explanatory comment documenting why it was removed and confirming the
correct assignment still follows.
