# Phase 999.4 Plan 01: D-01 Bounded Burst Datagram Send Summary

Replaced the single-datagram-per-16ms-tick policy with a congestion-aware burst loop in both session pumps (run_session and run_session_reattach), using `conn.datagram_send_buffer_space()` as the Layer-1 queue budget gate, draining the full deferred diff per tick when the path allows.

## Budget Path Decision: datagram_send_buffer_space vs Fixed Count Cap

**Path taken: `datagram_send_buffer_space()` (the preferred path).**

Verification: checked `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/quinn-0.11.9/src/connection.rs` — `pub fn datagram_send_buffer_space(&self) -> usize` is confirmed public on `quinn::Connection` in 0.11.9. The RESEARCH [ASSUMED A1] assumption is verified; the fixed-count fallback (`MAX_DATAGRAMS_PER_TICK`) was not needed.

The burst loop breaks when `conn.datagram_send_buffer_space() < cap` (Layer-1 application queue has less than one datagram's worth of free space) or when `result.deferred.is_empty()` (full diff drained). Under congestion, older datagrams in Layer-1 are dropped naturally (drop=true semantics) — correct for latest-state-wins.

## What Changed

**Task 1 — run_session burst loop:**
- Outer session `loop {` labelled `'pump: loop {` so nested send-error breaks escape correctly
- `diff_interval.tick()` arm: `if let Some(result) = build_state_diff(...)` block replaced with `loop { if conn.datagram_send_buffer_space() < cap { break; } ... build_state_diff ... }`
- `last_sent_snapshot = result.sent_cells` assigned INSIDE each burst iteration (Pitfall 2 compliance: prevents spurious epoch increments on the next call)
- Send-error arms use `break 'pump SessionEnd::TransportLost` to escape the outer loop
- CR-01/epoch_snapshots invariant and resume_complete guard preserved exactly

**Task 2 — run_session_reattach burst loop + test:**
- Identical burst loop applied to run_session_reattach; outer loop labelled `'pump: loop {`
- `if !resume_complete { continue; }` guard preserved (essential: resume_complete = true only after replay completes)
- New test `burst_drains_large_diff_in_one_tick` in `server::tests`: constructs 100 synthetic DiffRun entries, runs the build_state_diff burst loop at cap=50 bytes, asserts `pending_deferred.is_empty()` and `payloads_produced > 1` after the burst

## Test Design Note

The burst drain test uses a synthetic `pending_deferred` (100 DiffRun entries) with `last_acked_snapshot = last_sent_snapshot = current_grid`. This ensures `compute_diff_runs(current_grid, last_acked_snapshot) = []` (no fresh diff), so the burst loop processes only the synthetic deferred pile, which shrinks monotonically to empty.

Using an empty `last_acked_snapshot` (as on a real first connection) would cause a non-terminating loop: `compute_diff_runs` always returns the full screen at each iteration (fresh_runs are always added to the deferred pile), so the deferred pile never reaches empty. In the real pump this is not an issue because `last_acked_snapshot` advances via client acks between tick cycles.
